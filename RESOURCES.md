# Strategic Programmer Resources

## Knowledge

- [Book: _A Philosophy of Software Design_ by John Ousterhout — Stanford site](https://web.stanford.edu/~ouster/cgi-bin/aposd.php)
  Core text on complexity, deep modules, tactical vs strategic programming. Use for: codebase design, why comments-first and general-purpose modules win.
- [Episode: Pragmatic Engineer x Ousterhout on design + AI](https://newsletter.pragmaticengineer.com/p/the-philosophy-of-software-design)
  Why design matters more as codegen improves; design-it-twice, deep modules. Use for: Lesson 1 + 3 framing.
- [Book: _Test-Driven Development: By Example_ by Kent Beck (Pearson)](https://www.pearson.com/en-us/subject-catalog/p/test-driven-development-by-example/P200000009421/9780321146533)
  Red-green-refactor, test-first as verification harness. Use for: QA / verifying AI output lessons.
- [Guide: How to Write a Technical Spec — Template + Example](https://spec-coding.dev/blog/how-to-write-technical-spec-template-guide)
  7-section spec template, cost-of-late-clarity argument. Use for: Lesson 2 speccing for AI.
- [Guide: Spec-First Development with Claude (spec → plan → implement)](https://cc.bruniaux.com/guide/workflows/spec-first)
  intent.md → spec.md → plan.md chain, Spec Kit / OpenSpec flows. Use for: AI implementation workflow, Lesson 2 + 6.

## Wisdom (Communities)

- [r/code_review](https://www.reddit.com/r/code_review/)
  High-volume peer review practice. Use for: posting AI-assisted diffs, learning review checklist language.
- [r/ExperiencedDevs](https://www.reddit.com/r/ExperiencedDevs/)
  Moderated senior-level war stories on design, specs, debugging. Use for: wisdom on what actually fails in production.
- Local: JS/TS meetup or work code-review buddy
  Use for: real-time feedback on specs and module APIs. No opt-out recorded.
